# T12：单张线性FITS交接

起点为已推送的 `checkpoint/t11-files-verified-20261022`（9e6d238）。独立分支 `codex/fits-import-t12-20261022`；按用户要求，不读取或刷新Photoshop状态，所有原生项待用户手动验证。

## 首版数据约定

- 仅一幅未压缩的二维灰度或三平面RGB图像；允许空主HDU加一个图像扩展。其他表格的原数据保留在原FITS，不扩展成序列或通用多HDU管理器。拒绝拜耳阵列、相机原生RGB、未知轴布局、压缩图像及多幅图像。
- RGB须由用户明确指定线性ProPhoto或线性sRGB解释，不能从位深、直方图或`RGB`三个字推断色彩空间。sRGB按线性矩阵转换为本项目线性ProPhoto；不是测光颜色校准。灰度复制为三个相等的中性RGB通道，便于沿用现有线性准备，不虚构颜色。
- 使用已安装的Astropy读取原存储值，显式以float64计算 `BZERO + BSCALE × storage`；避免自动解码时提前量化到float32。逐块转为32位浮点TIFF，报告输出范围、舍入通道数与最大误差。不裁切负值或超1值，不以全局归一化掩盖范围问题。
- NaN/Inf、整数BLANK、float32无法表示的范围和不能精确进入float64的64位整数明确拒绝；不自动填零、裁剪、去拜耳或降低精度。存在float32舍入时须用户接受后才保存。
- 保留FITS原数组行顺序，不自动翻转、裁剪或旋转。全部HDU头卡片与原文件哈希作为归档写入TIFF描述；WCS仅存档，不宣称TIFF/Photoshop仍能解析它。用户后续几何变换不能据此沿用原解析状态。
- 原文件只读；检查和保存核对来源指纹，禁止同路径/硬链接覆盖。临时目录内完成并检查取消后原子替换目标；失败不破坏既有目标。
- 保存为带项目线性ICC的独立RGB TIFF，仍未拉伸。可显式打开，也可通过“使用刚保存的32位母版”进入原有范围准备；没有把浮点外来数据送入旧0..1去星入口。

依据：[Astropy图像及缩放](https://docs.astropy.org/en/stable/io/fits/usage/image.html)、[Astropy大图读取与缩放FAQ](https://docs.astropy.org/en/stable/io/fits/appendix/faq.html)。Context7核对了官方文档，实际调用以项目独立环境Astropy 8.0.1源码为准。本阶段不新增外部引擎或依赖。

## 验收

自动检查覆盖缩放整数、灰度、三平面、端序、float64舍入、负值/HDR、布局/颜色/空值拒绝、取消与来源变化、原文件不变、FITS→TIFF→范围准备，以及面板显式确认和过期检查。另用完整尺寸文件和冻结后台核对；实际数值结果在执行后补记。

Photoshop原生打开、ICC显示、正式文件选择和安装待用户手动验证；本阶段不执行这些操作。
