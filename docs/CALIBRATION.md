# 堆栈校准：使用方法与实现依据

2026-10-09 已完成新增数值测试、真实 Nikon RAW 暗场/偏置校准和 Siril 格式往返验证；具体结果及尚未覆盖的范围见 [验证记录](../VALIDATION.md)与[校准测试计划](CALIBRATION_TEST_PLAN.md)。现有 0.5.1 Release 不包含本次新增。

## 使用

在「堆栈」选择亮场照片后，展开「校准场（可选）」。暗场、平场、偏置场分别支持多选文件或选择文件夹，每类至少一张；文件夹只读取当前层级。清除某类选择即可不使用它。不选择任何校准场时保持原有无校准处理。

校准素材使用同一台相机、同一分辨率、RAW 位深/拍摄模式、裁切方式和 ISO/增益，选择尚未预校准的原始校准照片，不混用已去偏置的主暗场。暗场匹配亮场曝光与温度；平场保持与亮场相同的镜头/望远镜、光圈、焦距、对焦与光路位置，使用均匀照明且避免过曝。较长曝光的平场可另选「平暗场」，其曝光匹配平场；不把平暗场与亮场暗场混在同一组。校准帧越少，合成主校准场引入的随机噪声越大，通常应拍摄多张。

当前校准支持 LibRaw 能解码的原始 **RGB Bayer RAW**；X-Trans、非 Bayer、非正方形像素、已经去马赛克的 LinearRaw DNG 暂不支持校准。它们原有的无校准堆栈能力不因此改变。另一条入口是 16/32 位线性 TIFF：需明确勾选「TIFF 已线性显影并去除黑电平」，且仅接受无 ICC（假定线性 ProPhoto RGB）或本项目线性 ProPhoto ICC。不能把普通相机 JPEG/PNG、带非线性色调处理的 TIFF 当作传感器校准数据，也不能混用原始 RAW 与已显影校准场。

## 可选组合与依赖

| 选择 | 处理与前提 |
| --- | --- |
| 全部不选 | 原有无校准堆栈。 |
| 仅偏置场 | 合成主偏置并去除剩余电子偏置信号。 |
| 仅暗场 | 匹配暗场本身包含偏置；不要求另选偏置，不缩放暗场。 |
| 暗场＋偏置场 | 主暗场先去偏置，亮场再分别去偏置与暗信号，避免重复扣偏置。 |
| 仅平场 | RAW 先去照片自带的每通道黑电平，再合成平场；线性 TIFF 依赖用户声明已去黑电平。该近似不保证消除传感器的剩余偏置纹理，宜视相机情况补拍偏置。 |
| 平场＋偏置场 | 平场先去偏置再合成；偏置也用于亮场。 |
| 平场＋暗场，无偏置 | 亮场使用匹配暗场；平场使用自带黑电平。若平场与主暗场曝光恰好匹配，同一暗场也用于平场。不能直接用长曝光亮场暗场扣除短曝光平场。 |
| 暗场＋平场＋偏置场 | 按上述规则组合；需要时增加平暗场。 |
| 平场＋平暗场 | 匹配平暗场一次性去除平场偏置及热信号；不要求再给平场扣一次偏置。仍可为亮场选择独立暗场/偏置。 |

平暗场只在选择平场时有意义。**没有“用平场就必须选择一组偏置照片”的统一限制，但平场的偏置必须得到处理**：实测偏置、匹配平暗场，或适合该相机的 RAW 元数据黑电平。元数据黑电平是每通道常量近似，不能替代所有相机的偏置纹理、光学黑区/overscan 模型或其他专用传感器校准。

默认不做暗场曝光缩放，也不通过优化目标猜测一个暗场系数。已知曝光/ISO 不匹配会报错；通用元数据缺失时给出提示，由用户确认拍摄条件。LibRaw 提供 RAW 曝光与 ISO，ExifRead 补充相机型号及 TIFF 信息；通用 RAW/EXIF 通常不能可靠提供传感器温度，因此不声称已自动匹配温度。

## 研究与开源复用

先查阅官方工作流与实现，再确定处理顺序，而不是只据单一校准公式实现：

- [Siril 1.4 校准文档](https://siril.readthedocs.io/en/stable/preprocessing/calibration.html)：可选校准、主校准场、暗场匹配、CFA 平场均衡、校准后去马赛克；暗场缩放需区分偏置与热信号。
- [Siril Synthetic biases](https://siril.org/tutorials/synthetic-biases/)：现代传感器用恒定偏置近似可避免引入不必要的偏置帧随机噪声，但应评估实际相机的偏置结构。
- [Astropy 实际平场校准示例](https://www.astropy.org/ccd-reduction-and-photometry-guide/v/dev/notebooks/05-03-Calibrating-the-flats.html)：匹配暗场可以一次去偏置和暗信号；暗场缩放时需分开处理偏置。
- [ccdproc 2.5.1 core.py](https://github.com/astropy/ccdproc/blob/2.5.1/ccdproc/core.py) 与 [combiner.py](https://github.com/astropy/ccdproc/blob/2.5.1/ccdproc/combiner.py)：直接调用 `subtract_bias`、`subtract_dark(scale=False)`、`flat_correct` 与 `Combiner`，保留其实际算法；主校准场不少于五张时使用中位数/MAD 的双侧 3σ 剔除，再以 float64 合成均值。少于五张使用均值，不做不稳定的小样本 Sigma 剔除。
- [Colour v0.2.6 Malvar2004 实现](https://github.com/colour-science/colour-demosaicing/blob/v0.2.6/colour_demosaicing/bayer/demosaicing/malvar2004.py)：适配 BSD 开源的浮点 Bayer 去马赛克，保留卷积核和采样规则；采用分块及两像素 halo，避免完整 RGB 掩膜和多个全尺寸临时卷积数组。没有把校准后的浮点 CFA 塞回 16 位 LibRaw 缓冲区。
- [rawpy v0.27.1 源码](https://github.com/letmaik/rawpy/blob/v0.27.1/rawpy/_rawpy.pyx)：核对完整传感器与可见区域的 Bayer 相位、黑电平、曝光与旋转信息。
- [Astropy FITS 图像与缩放](https://docs.astropy.org/en/stable/io/fits/usage/image.html)：标准浮点 FITS，以及整数 FITS 的 BSCALE/BZERO 物理值映射。

校准后的 Bayer 顺序是：读取未去马赛克传感器数据 → 按元数据去黑电平 → 实测剩余偏置/暗场校正 → 平场校正 → float32 Malvar 去马赛克 → 按拍摄方向旋转 → 原有星点配准与堆栈。仅线性 TIFF 已经去马赛克，在已有线性 RGB 平面校准。

本流程所有 RAW 都先去元数据黑电平；实测主偏置表示扣除此常量后的剩余偏置。暗场先去主偏置时，亮场再去主偏置与主暗场；不选偏置时，直接去包含剩余偏置的主暗场。匹配平暗场不再单独重复扣主偏置。

每一张平场在去偏置/平暗场之后按四个 Bayer 位置（RGB TIFF 按三个通道）分别归一化，然后合成与再次归一化主平场；这保留相机的颜色比例，避免把平场光源的色温直接变成星点颜色校正。对亮场不做逐帧曝光、白平衡或亮度归一化。应用主平场时固定 `norm_value=1`，不重新按每个分块均值归一化，以免抹掉真实暗角。

主平场中非正响应不能可靠相除；当前会明确报错，不用人为抬高除数或补造像素来掩盖错误。自动坏像素插值尚未实现。单帧平场超过 0.1% 传感器采样饱和则拒绝使用；不能恢复拍摄时已经饱和的信号。

## 精度与性能边界

- 校准 RAW 不经过 LibRaw 的 16 位 `postprocess`：整型 ADU 转 float32 后做减法与除法，不截断负值或超过 1 的高光。所有亮场统一使用中间基准帧的同一个 ADU 比例；颜色矩阵和基准白平衡保留。无校准 RAW 仍沿用原来的线性 AHD 路径。
- 主校准场只合成一次。每类帧逐张解码到浮点磁盘缓存；合成输入块控制在约 32 MiB 内，ccdproc 的中间数组另有开销。校准与去马赛克按小块处理，取消在分块边界响应。均值仍以 float64 累积。
- 本机 20 张 6064×4040 Nikon NEF、30 张匹配暗场、36 张偏置的均值校准堆栈实测约 346 秒，诊断进程峰值工作内存约 3751 MiB；这是一次本机测量，不是通用速度承诺。50/100 张已做 512×512 合成容量测试，全尺寸仍待验证。100 张 2400 万像素 Bayer 校准缓存约 8.9 GiB（按当前正在合成的一类），另需主校准场、堆栈缓存及输出文件空间。
- 校准消除固定偏置、暗信号与响应不均，不会让单帧随机噪声凭空消失；测得的主校准场也会引入噪声。多张主校准场合成、合理剔除及最后堆栈用于减小这部分影响。缺少校准场不应强行伪造它们。

“最大信息保留”不等于全过程无损：传感器饱和、RAW 原有压缩、去马赛克、星点重采样和有限精度计算都有边界。默认 DNG/32 位浮点输出避免额外的整数截断；始终保留原片。

## 输出与 Photoshop

默认 **32 位浮点 LinearRaw DNG**，另可选 16/32 位 TIFF、16/32 位 FITS。

- DNG 保留相机线性 RGB、颜色矩阵和白平衡；已去马赛克，不能替代原始 CFA RAW。Camera Raw 打开的文档位深由其设置决定。
- 32 位 TIFF 转为带 ICC 的线性 ProPhoto RGB，保留负值和超范围高光。
- 16 位 TIFF 最终量化，负值截零；高光必要时全图统一缩放。选择前面板说明这项信息损失，JSON 记录比例及截断数量。
- 32 位 FITS 保存线性 RGB 浮点三平面，保留负值及高光；颜色空间、矩阵、白平衡、校准来源与数量写入 `STARMETA` JSON 扩展，采集参数写入常见 FITS 头字段。不伪造 WCS/天体坐标。
- 16 位 FITS 用 `BITPIX=16` 的有符号整数及 BSCALE/BZERO 覆盖结果的完整正负范围，最后一次量化；记录量化步长，不能表示任意浮点精度。Astropy 独立读取符合半个量化步长的误差界限；**Siril 1.4.2 会将此类缩放整数读入 uint16，无法保留原来的负值和浮点范围，即使设置 `set32bits` 也不能恢复**。需要继续在 Siril 处理时请选择 **32 位 FITS**；实际往返验证其负值及大于 1 的高光逐像素保留。Siril 的内部数据类型说明见 [官方 API 文档](https://siril.readthedocs.io/en/stable/Python-API.html)。
- 原生 Photoshop 不直接读取 FITS，因此所选 FITS 保存后，使用 **同一份未量化的浮点堆栈结果**生成插件临时 32 位 TIFF，并在 Photoshop 打开它；即使选择 16 位 FITS，PS 中也继续使用量化前的结果。临时文件由 UXP 管理，后续编辑请另存 PSD/TIFF。只打开结果，原始亮场和校准场不在 Photoshop 打开。

同名 JSON 记录亮场顺序、基准、变换、色彩、校准文件与采集信息、方法、提醒以及输出编码。处理不会修改源文件。README、格式说明与测试计划分别描述设计行为、已完成检查与待验证项目，不把未测试行为当作验证结论。
