# 线性母版准备：T4 数据约定

基线为已同步 GitHub 的 `16296e4` / `checkpoint/0.7.1-candidate-20261018`。本轮只实施调研报告T4；背景梯度和受保护拉伸分别留给T5、T6。

## 首版支持范围

入口读取磁盘文件，不经当前 `0..1` 图层上传接口，不放松 `validate_image()`。首版仅接受 **Star Studio 导出的、尚未拉伸的32位浮点RGB TIFF**：单幅、连续RGB、无透明通道、无压缩/瓦片，包含与本项目生成值完全相同的 `Star Studio Linear ProPhoto RGB` gamma1 ICC及原导出标识。用户仍需明确确认未拉伸；位深、直方图、ICC和软件标识本身不能证明照片从未被编辑。

DNG、FITS、灰度、外来sRGB/Adobe RGB/Display P3、缺失或其他ICC均不在首版自动准备范围内。它们原有工作流不受影响。NaN/Inf（包括无覆盖边界）明确拒绝，本版需使用完全有限的有效母版；不自动裁剪或填零，不能为重试而悄悄改写母版或其来源标识。

## 独立范围映射

读取源float32块，在float64中统计并计算。输入最小/最大值为 `lo/hi`，令 `offset=min(0,lo)`，`span=max(1,hi)-offset`，`scale` 为不小于span的最小2的整数次幂。RGB全图共享同一映射：

```text
prepared = float32((source - offset) / scale)
source_estimate = float64(prepared) * scale + offset
```

不按通道归一化，不做百分位黑白点、不做clip，也不进行ICC转换、gamma编码、非线性拉伸或降为8/16位。原值已处于0..1时映射为恒等；只有正高光溢出时，2的幂缩放避免不必要的乘除舍入。含负值时需共同抬升零点，此时颜色比例可能变化，不能宣传为保色或测光校准。

有限float32副本不可能保证任意动态范围的所有差异都精确可逆。必须记录offset/scale、原始范围、负值/高光计数、舍入改变通道数、最大重建绝对误差和相对全范围误差；界面明确显示舍入结果。**母版原文件保持不变**，映射副本不能代替原母版。不会以“所有值进了0..1”宣称无损。

源文件在检查与执行间如发生大小或修改时间变化，要求重新检查。执行重新统计源数据，不信任界面传来的范围。输出不能是源文件本身或其硬链接。按块处理并使用磁盘暂存，临时额外空间约为两份RGB float32图像；失败/取消在提交前清理暂存并保留既有目标文件。

## 副本、显示与处理阶段

用户选择新的TIFF保存位置；成功后只打开该完整分辨率32位副本。复制原ICC字节，在TIFF描述中写入来源、检查指纹、映射、误差和 `stage=range-prepared-linear`。生成文件标记为已准备，首版入口拒绝再次准备，避免重复抬升或缩放。其他软件重存可能移除标记，不能将其视为通用跨软件追踪系统。

打开后核对Photoshop文档的尺寸、32位及配置名称，不改变全局颜色管理。若不符，关闭本次新开的文档并说明已保存文件仍可用。当前会话将已知副本标记为线性，去星仍要求显影后的独立副本。

**这一任务没有显示自动拉伸，也没有应用非线性拉伸。** PS中的正常ICC显示不是额外的自动提亮；准备后的照片仍可能暗。界面明确显示“已创建范围准备副本 / 仍为线性 / 未拉伸”。T6随后在此数据约定上实现显示与实际拉伸，不能把本次范围准备称为已显影。

## 验收

1. 合成float32母版含负值和大于1高光，通过独立文件入口；源文件逐字节不变，结果范围符合0..1且未裁切，映射和误差与独立计算一致。
2. 普通范围恒等、同一RGB映射、浮点极值、NaN/Inf、错误ICC/位深/透明度、重复准备、源变化、失败和取消均有行为检查；旧上传仍拒绝超范围值。
3. Photoshop原生检查完整尺寸、32位、线性ProPhoto配置及读回像素；准备后仍标记线性，不自动去星。其余ICC不得仅凭mock宣布支持。
4. 保存独立功能提交及候选回退范围，在独立副本实际回退后核对原有检查。安装包重建运行组件，不能复用未包含新模块的旧冻结程序。

## 资料依据

- [Siril：显示与实际拉伸](https://siril.readthedocs.io/en/stable/processing/stretching.html)：显示变换与修改像素不同；MTF前的黑白范围映射也不同于后续非线性变换。本任务仅使用全范围、公共通道的仿射映射，不移植其自动黑点或拉伸算法。
- [tifffile 官方内存映射文档](https://github.com/cgohlke/tifffile/blob/master/_autodocs/01-core-functions.md)：只读映射已有无压缩/瓦片TIFF，另建输出；使用现有开源TIFF实现而非自写文件编码。
- [Adobe UXP Document](https://developer.adobe.com/photoshop/uxp/2022/ps_reference/classes/document/)：核对文档尺寸、bitsPerChannel与colorProfileName，避免自动换配置或降低位深。

上述是实现前约定；实际数值、原生验证与未覆盖范围见 [VALIDATION.md](../VALIDATION.md)，不将约定本身当作已通过的测试。
