# T25：分离明确失败后的输入清理

基线6fbf2a6（`checkpoint/t24-core-preview-page-exit-20261022`），分支`codex/core-extract-failure-cleanup-20261022`。本项只修基础分离的失败清理，不加参数、引擎、算法或专业功能，不读取或操作Photoshop，不恢复已跳过的素材下载和对应验证。

## 根因与最小修改

`extract()`先上传完整图层，再等待`job()`。原清理块只包住结果写回；后台返回错误时在进入清理块之前退出，已上传的输入仍留在组件的图像表及临时浮点文件中，重复重试会继续增加这些已结束作业的输入。

`job()`现在只为后台明确返回的`error`、`canceled`异常标记对应终态。分离捕获这两类异常后释放本次输入，再继续抛出原原因；清理失败仅记错误，不替换引擎的原始错误。成功和写回失败仍沿用原输入/两张输出的完整清理，图层事务不变。

**创建或轮询回复丢失不代表后台已经停止。** 没有明确终态时保留输入，不能在通用`finally`中无条件删除仍可能被工作线程读取的映射。本项没有实现失联作业的自动恢复或延迟清理，也没有增加StarNet中途取消能力；仅正确处理已经收到的终态。

## 证据与边界

- 四项复现先失败：明确引擎错误、协议取消终态、失败后重试不累积输入、清理失败仍保留原错误。修复后全部通过。
- 分离专项13项、完整Node286项通过。另核对创建/轮询回复丢失保留工作输入，成功的8/16/32位及两类分离约定不变，写回失败仍释放三份完整缓存；不会向`/images/undefined`发清理请求。
- 使用模拟SDK、模拟协议状态和输入集合检查清理行为，没有执行PS原生读写、真实引擎失败或GPU推理；不能据此证明原生界面或所有失联情形已验收。

## 2026-11-04 Photoshop 原生复验

在 Photoshop 27.1 的 0.24.8 隔离面板中，从同一张 512×512 RGB16/sRGB 合成图执行三次分离。前两次使用 StarNet2 2.6.2-0242 的独立测试副本，模型文件存在且非空，内容为故意写入的无效 ONNX。第三次在同一面板切回已授权的有效安装。由测试按钮触发正常面板事件，使用隔离端口预启动冻结组件，宿主写回模块与源码逐字节一致。

- 两次失败均进入实际 StarNet 进程。后台报告非零退出，面板显示同一份原始错误。失败作业没有输出图层或星点结果，原图层顺序、可见性和历史状态保持。
- 三次上传采用不同输入 ID，传给引擎的浮点 FITS 像素逐值一致。每次失败后原输入 ID 无法再读；成功后输入和两张输出的缓存都被释放。检查隔离作业目录时，剩余图像映射文件为 0，诊断用引擎日志与 FITS 文件保留。
- 有效模型经 DirectML 推理成功，单次引擎耗时约 2.62 秒。Photoshop 创建 `_starless` 和默认隐藏的 `_starmask`。失败后、成功后和一次撤销后的原层均与初始原层逐值一致，每组比较 786,432 个 RGB 通道。将两层的 16 位读回值按滤色公式合成，最大误差约 2.86 个 16 位码值。

此复验覆盖已明确失败的恢复分支。通信中断期间保留工作输入仍由协议回归覆盖，许可确认、旧 CPU 版原生失败恢复、正式安装和真实题材画质有各自的验收范围。测试结束时已关闭合成文档、移除临时面板并停止隔离后台。本地证据见 `artifacts/t25-native-20261104/native.json` 和 `verification.json`。
