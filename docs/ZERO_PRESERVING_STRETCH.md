# T21：保留零点的线性提亮

基线 `checkpoint/t20-real-files-verified-20261022`（813c1a9）。T20实拍证明：现有T4全局offset抬升了零点，后续T6虽然保持准备副本的RGB比例，却不能恢复母版的颜色比例。本任务只修复这一明确的交接限制；不以裁切负值、再次去星或模糊代替。

## 先核对开源路径

2026-10-22核对Siril官方文档与固定版本源码，未运行Siril或StarNet推理：

- [StarNet Python脚本，提交7db811b](https://gitlab.com/free-astro/siril-scripts/-/blob/7db811b4c55d718a7715593f606cd7fd6b33f6d3/StarNetAstro/StarNet.py)：236–290行的转换会把负值clip到0；304–314行通过16位整数TIFF交接；335–411行的逐通道MTF包含黑端裁切，逆变换是近似恢复。该文件声明GPL-3.0-or-later，不能仅据仓库根MIT许可判断。
- [Siril 1.4.2 C实现，提交0516004](https://gitlab.com/free-astro/siril/-/blob/051600402c52ddb92d18350f074f758e6c46a354/src/filters/starnet.c)：524–599行同样含float范围缩放、MTF预拉伸和16位TIFF交接。[当前官方说明](https://siril.readthedocs.io/en/stable/processing/stars/starnet.html)区分旧C与新Python路径，未承诺无损。
- 本地仅抽取经过阅读的7个纯NumPy辅助函数，以恒等引擎模拟同一实拍母版的往返，不导入整份外部脚本。743个负通道被裁掉；本张正值MTF黑/白端裁切均为0，但16位交接使73,415,912个通道改变，非负通道最大绝对误差约1.054×10⁻⁴。这不是Siril程序或实际去星的质量/性能比较。

因此不把该流程直接替换成“无损去星”。复用本项目已有、源自Siril的modified asinh标量曲线；依据仍为 [Siril拉伸与颜色模式](https://siril.readthedocs.io/en/stable/processing/stretching.html)。不引入新引擎、依赖或外部程序许可。

## 最小输入与数值约定

1. 现有T4输入和0..1契约保持。新增直接读取Star Studio原导出的单幅、无压缩、RGB float32、精确线性ProPhoto ICC母版；沿用`master_data`的来源/布局检查。选择文件后须明确确认仍未拉伸，不能从像素自动判断线性状态。
2. 不改变原母版，不做T4 offset/scale。仍使用三项现有控制：提亮、亮星保护、背景亮度。每个像素`p=max(abs(R),abs(G),abs(B))`，共同正增益`curve(p)/p`，全零像素增益1；三个通道保持同一真实零点。超过1的输入沿用既有曲线高光保护线性尾段，不截断。
3. 自动建议只在含正值像素中采样绝对峰值，目标中位峰值约0.15；它不是天空测量或最佳审美。中间float64、最终float32；0强度逐位恒等。非有限结果、非零舍入为0或符号改变应拒绝，不能裁切或填零。保存记录真实范围、负值/超1数量和存储误差，不声称无损。
4. 独立快照、指纹变化失效、参数变更重新计算、取消清理和不覆盖来源的保护复用T6。另存为32位TIFF，使用明确不同的来源种类，输出不能冒充未拉伸母版/T4输入。
5. 文件选择入口接受上述两种已定义来源，不增加模式参数。界面在读取后说明采用哪条路径；原来的“使用刚准备副本”继续可用。新路径如仍含负值或超1，必须说明旧0..1去星/背景工具不接收，不放松`validate_image()`。
