# T22：星点加工的无效图层选择与恢复

基线465b105，分支`codex/core-preview-selection-20261022`。按用户最新优先级，只修基础流程，不下载素材、不做对应离线素材验证，不加入专业能力或操作Photoshop。

## 复现与修复

选择星点11并完成预览后，再把背景也设为11：旧代码仅发一次错误消息，预览提示仍可能写“已更新”；若同时启用效果，还会读取/加工无法合成的星点。执行路径也在计算后才检查背景，浪费大图处理时间。

修复将这类来源错误作为明确状态：显示“图层选择无效”和旧画面说明，停止排队并请求取消已有任务，禁止比较/执行。已经发起的读取或后台任务仍等到安全结束，不提前释放正在使用的图像；晚到的结果不能更新预览。执行入口先检查背景，再决定是否读取和计算；写回前仍重新读取背景，期间删层会停止并释放未使用结果，不持有过时引用写回。

改正选择后自动恢复；同一来源/参数的有效缓存继续复用，不要求刷新、重新选星点或重新上传。原图层选择、参数、背景可选、混合方式、编码、像素算法和撤销逻辑不变。

## 证据与边界

- 原三项复现检查均失败：无效背景仍显示计算/已更新、已有任务未请求取消、旧合成仍被标成最新。修复后通过，另补任务ID晚到、结果在取消前完成两个竞态，并检查执行期间删层仍在写回前拒绝；完整Node **272项通过**。
- 新检查覆盖无效选择时不上传/不创建像素任务/不应用、等待取消后不重复计算、不提前删除输入、过时原生回调不能报已更新，以及修正选择后复用已有完整结果。使用模拟SDK，没有执行PS原生验证。
- 后台、数值算法及依赖未改；Python数值证据沿用T21，不通过重复跑数值测试冒充本次UI证据。开发包复用T21已执行的后台时，须逐文件确认runtime一致，并单独核对新manifest的健康版本。
- 本项PS的错误提示、误选期间实际画面、纠正后预览/执行/撤销仍待用户手动验证。T7与此前待办保持；本项不能作为整体完成或正式发布依据。
