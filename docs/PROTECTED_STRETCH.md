# T6 受保护拉伸约定

基线：`checkpoint/0.9.0-candidate-20261021`。本阶段补齐 T4 范围准备之后的初始拉伸；不以此默认接入线性去星，也不把已有显影照片自动再拉伸。

## 输入与状态

- 首版接收 T4 原样保存的 `starstudio-range-prepared` TIFF：有限、0..1、无压缩、单幅RGB float32、完全相同的线性ProPhoto ICC，以及“仍未拉伸”的用户确认。普通sRGB/AdobeRGB/DisplayP3显影照片、其他ICC、灰度/alpha、原始HDR母版及本功能已拉伸的输出不冒充这种来源。
- 缓存沿用现有传输限制：总像素不超过250M、单边不超过65536；不以自动裁剪或降低位深适配超限图像。
- 保留原母版和范围准备副本。读取磁盘副本，不带入PS尚未保存的编辑；使用快照、文件指纹及原始范围映射记录来源。源文件变化后重新读取，不对上一次预览重复叠加曲线。
- 三个状态分别呈现：T4“已创建后期副本、仍线性”；T6“仅查看提亮、未应用”；显式保存/输出后“已应用拉伸”。预览使用临时PS文档承载显示用像素，原母版及准备副本始终不变；不能把临时预览中的改变称为源文件已应用。

## 数学与信息边界

- 已核对仓库 `vendor/siril-ght.c` 的 modified asinh 与现有 `stretch_curve()`：LP/SP/HP的受保护切线及归一化可复用。旧 `stretch()` 使用固定sRGB亮度权重，并带RGB裁切/混合，不直接用于新的线性ProPhoto路径。
- 首版复用标量 modified asinh，以RGB最大分量作为共同伸缩参照。非黑像素 `p=max(R,G,B)`，`g=curve(p)/p`，三通道共同乘g。它不是感知亮度，也不是完整Siril颜色模式复刻；避免固定sRGB权重和逐通道白平衡变化。
- 在确定的线性ProPhoto空间中，共同正比例理论上保留RGB比例及XYZ色度；实际输出float32必须测量误差，不能宣传任意ICC下无损保色。T4负值映射已抬升零点时，T6不能恢复此前改变的颜色比例。
- 控制为提亮程度 `ln(D+1)` 0..10、亮星保护0..1、背景亮度0..1。HP随亮星保护从1降至0.3；背景亮度用同一输入快照的中位峰值控制SP，LP与黑点固定为0，不自动压黑、不截高光。显示实际SP/HP及建议依据。
- 自动建议仅寻找采样中位峰值约0.15的保守起点，默认亮星保护0.75、背景亮度0.8；不推断真实天空背景、线性状态或最佳审美。平坦、无可靠正值、已偏亮或超出控制范围时，给出原因，保留手动调整。
- 中间计算float64；仅最终存储float32。复用曲线时保持float64到共同增益之后再舍入。0强度为逐值恒等；黑点和白点不移动。输出反馈新增0/1端点、近饱和数量及最大存储舍入误差；浮点压缩仍可能合并等级，不能只凭没有clip声称无信息损失。
- 预览允许检查不合适参数，但保存时若非端点源像素新增0/1端点，拒绝应用，提示降低强度或增加亮星保护；不靠nextafter夹值隐藏等级合并。0强度副本仍标线性，不标成已显影。

## 输出与验证

- 全分辨率32位PS预览，原输入与当前效果比较；实际结果用同一快照和参数。显式保存独立32位TIFF，保留ICC、来源映射、曲线参数、阶段和精度统计，并在PS创建可撤销的结果层副本。
- 不覆盖准备副本或记录的原母版（包含硬链接）；取消、失败或源变化时不提交文件，释放输出缓存；保存成功而PS打开/输出失败时，说明已保存的位置，不误报已在PS应用。
- 自动检查：与数值积分参考比较受保护标量曲线；暗背景/高光/亚正常数/强色像素、端点、零强度、RGB比例与XYZ色度；重复重算、非法输入/来源变化/重复拉伸、取消与保存保护。
- Photoshop实测：已知线性ProPhoto输入的全尺寸、ICC、预览/文件/最终层一致、源不变和撤销；24MP记录性能与检查范围。真实银河/星云与人工文件选择的证据单独记载，不用mock替代。
- 本任务只在独立分支推进；功能与验证各自提交，完成后再建立候选回退点并同步main。整个调研目标仍包括后续任务，不以T6一项代表全部完成。

依据：[Siril 拉伸与颜色模式](https://siril.readthedocs.io/en/stable/processing/stretching.html)、仓库Siril标量实现、[Adobe Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)。

## 实现检查点

- 约定提交 `baec9e3`；asinh精度修复单独提交 `a9378b1`，标签 `checkpoint/t6-asinh-precision-20261021`。后台检查点 `0ef42d3` / `checkpoint/t6-backend-20261021` 与前端分开保存。
- 后台任务：`stretchInspect` 要求明确未拉伸确认，严格验证T4文件并建立只读来源的独立快照；返回 `image`、来源/范围映射、采样分位数和建议。`stretchRender` 从该快照重算，返回结果image及真实精度/端点统计。`stretchSave` 只接受后台关联的渲染结果，不信任前端传来的统计，保存带完整来源的独立TIFF。
- 旧标量asinh直接相减会把远小于SP的正值抹成0；现在用等价的稳定区间计算。9组独立导数积分参考包含1e-45暗值、SP与高光切线；新增路径在float64共同增益后才存为float32，并跳过旧函数末端裁切，范围异常拒绝。
- 前端显式选择T4准备副本，提供“使用刚准备副本”快捷入口；临时复制采用真实UXP File.copyTo/getTemporaryFolder，在插件自己的临时目录打开PS，避免将用户已打开且可能有未保存改动的文档当成磁盘快照。只清理本次复制文件与空目录，未知条目保留，后台缓存在清理失败时仍释放。实际SDK拒绝非空Folder.delete，已按真机行为修正，不依赖旧文档的递归删除说法。
- 复用宿主32位原输入/结果双层路径，并参数化显示和历史名称。显式保存后从同一结果创建可撤销图层；0强度仍标线性。源变化、未查看当前参数或新增0/1端点时，不应用。比较原输入期间改参数，需要重新查看新提亮效果才能应用。
- 后台依赖本轮标量精度修复；回退时先撤依赖它的T6任务，再撤精度提交。完整候选完成后，再以0.9.0基线到候选标签的整个范围实测回退。
