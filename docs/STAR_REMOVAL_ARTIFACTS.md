# 星点位置彩圈：真实素材调查

2026-10-10，在所有者提供的真实带地景星空素材上复现。原始 RAW、DNG 和 PSD 仅读取，处理与导出均位于项目忽略目录 `artifacts/starnet-rings/`。已增加默认关闭的「保留模型背景（减少彩色残留）」选项；不勾选时保持原有分离行为。

## 使用的输入

- 该组有28张 NEF。已有 `StarStudio_stack.dng` 的记录为28帧均值、30张暗场、36张偏置、无平场，输出4040×6064相机线性RGB float32，没有负值或高光截断。
- 用户保存的 `lights/StarStudio_stack.psd` 为6064×4040、RGB16、Display P3。复制后的「图层 1」与「背景」导出逐像素一致；去星层位于 Color Efex Pro 5 处理层下方，调查直接使用未经过该处理的来源层和去星层。
- PSD的 Camera Raw 元数据中曝光、对比度、清晰度、去雾、自然饱和度、饱和度均为0，吻合用户没有手动调色的描述；默认锐化为40，半径1，细节25，彩色降噪25。默认显影也会影响星点边缘。不能仅凭元数据断言锐化是全部彩圈的来源。
- Display P3 的RGB传递曲线为分段2.4曲线，此RGB16图层不是尚未显影的相机线性数组。不能因为来自DNG便直接开启 StarNet 的 `--linear`。

## 已定位的原因

原图的部分星点边缘有通道相关的暗色凹陷。去马赛克、带负旁瓣的重采样、镜头像差和默认锐化可能参与形成这些结构；本次没有分别隔离它们的贡献。模型移去亮星并填回背景后，仍可能留下小尺度彩色纹理，这部分是模型局限。

插件的 `backend.algorithms.separate` 为保持黑底星点非负、并能用滤色/添加重建原图，对背景逐通道执行 `minimum(模型输出, 原图)`。只要某个星点边缘通道低于模型填回的背景，该通道就重新取原图的低值。这一步明确重新引入和加重了彩圈，而非 Photoshop 写回才产生彩圈。

这个约束有真实的数学冲突：若模型背景B高于原像素O，对应差值 `O-B` 必须为负；普通黑底、仅提亮的星点层无法同时保存该负差值、保持模型背景、并精确重建O。直接取消限制并仍截掉负星点，会在重建时丢失这部分修正。

## 完整尺寸对照

新版 StarNet2 2.6.2-0242，DirectML GPU，256步长，同一份完整尺寸RGB输入；不做蒙尘与划痕、克隆、局部模糊或颜色清洗。

| 对照 | CLI耗时 | 100颗亮星的局部彩色残留指标中位数 |
| --- | ---: | ---: |
| 默认模型输出，执行当前背景限制 | 28.06秒 | 0.07654 |
| 默认模型输出，保留填回的背景 | 同一次推理 | 0.03961 |
| 2倍推理采样，执行当前背景限制 | 101.06秒 | 0.07411 |
| 2倍推理采样，保留填回的背景 | 同一次推理 | 0.02888 |
| `--linear`用在该已显影图层，执行当前限制 | 31.41秒 | 0.07640 |

指标定义：从原图选择100颗相距至少60像素的亮星；每颗取48×48块，用半径18–23像素环带的逐通道中位数估计局部背景；半径12像素内计算RGB背景偏差的最大通道差，并取95百分位，最后汇总100颗的中位数。单位为归一化通道值。这是同图对照的残留代理指标，没有无星背景真值，不能解释为天文信号准确率或所有星点的改善承诺。

保留默认模型背景的指标比当前分离结果低约48%；保留现有背景限制时，2倍采样仅改善约3%，却增加约3.6倍推理时间。因此应先解决分离表示方式，再决定是否为细小星点使用2倍采样。模型背景本身仍可有彩色纹理，不能承诺完全消除。

## 不追加模糊的可行方案

保留模型背景，并保存完整的正负差值。信息保留优先时应使用32位浮点存储，正负差值均保留，用添加重建。插件根据当前文档位深自动选择表示方式：8/16位使用灰底编码和线性光，32位使用有符号浮点差值和线性减淡（添加）；不更改文档位深或ICC。

星点加工会解码修正层，使用既有算法调整正星点信号，再原样加回负差值。负差值不参与辉光、曲线或星形重建。灰底层由其线性光模式识别，来源图层即使改名仍能识别；请保留此模式，预览和加工输出也保持线性光。32位加工可接收 `-1..1` 的星点差值，超出范围仍拒绝，不自动剪裁或归一化。

另用16×16合成float32数据在 Photoshop 原生验证了正负星点层的线性减淡（添加）混合，重建逐像素一致；这确认了原生混合可行，不代替完整真实素材的32位工作流验证。记录为 `signed32-report.json`。

针对现有RGB16图层，验证了50%灰底编码：`星点编码=(原图-模型背景+1)/2`，使用 Photoshop「线性光」混合。它将负修正保存在灰色以下，正星点保存在灰色以上；不追加空间滤波，但编码和16位写回仍有量化。不能把这种星点层当作普通黑底层使用滤色，也不能未经解码直接套用现有星点加工算法。

在 Photoshop 2026 中，完整尺寸的该组合重建原图最大误差为2/65535，模型背景写回最大误差为1/65535；ICC完全一致，原PSD的SHA-256不变。浮点编码算术的重建最大误差为1.19e-7，不能称为逐比特无损。示例PSD保留隐藏原图、模型背景和灰底修正星点层，当前展示背景。

原生示例：`artifacts/starnet-rings/PS-ring-preserving-split.psd`；对照图：`comparison-summary.png`；定量记录：`ring-metrics.json`、`user-full-benchmark.json`、`native-signed-report.json`。这些素材不进入源码或公开安装包。

更早的线性工作流可在32位线性结果上调用 StarNet 自带MTF预拉伸/逆变换，并在去星后再锐化。新版CLI对超过1的线性高光会警告并截断；接入时必须先采用可逆的统一缩放并恢复原尺度，不能直接吞掉高光。其阴影恢复、2倍采样和模型估计也不等于无损背景恢复。

## 上游依据

- [StarNet 官方输入、线性数据与输出说明](https://starnetastro.com/documentation/starnet/pixinsight-module/)：线性数据经STF/自动拉伸后逆变换；恢复拉伸截掉的阴影；输出不保证精确重建原图。
- [StarNet 官方使用建议](https://starnetastro.com/documentation/starnet/tips-and-tricks/)：RGB整体处理、根据星点尺度选择步长、细小星点可尝试2倍采样，耗时约4倍且可能影响大星点。
- [Siril StarNet 文档](https://siril.readthedocs.io/en/stable/processing/stars/starnet.html)：预拉伸线性图像、完成后逆变换；2倍采样不是普遍更好的默认设置。
- [Adobe 混合模式说明](https://helpx.adobe.com/photoshop/desktop/repair-retouch/adjust-light-tone/blending-mode-descriptions.html)：线性光根据混合色亮暗执行加深或减淡。上述数值重建另在本机完整尺寸原生验证。
- 新版CLI选项、负阴影恢复、高光截断及float64 MTF行为另外直接核对已安装发行包的 `--help`、`README.txt`，不依赖旧版CLI说明。
