# Star Studio 功能调研与 AI Agent 改进建议

调研日期：2026-10-18。面向 Photoshop 中的星空后期入门用户，同时覆盖银河地景与深空照片。

本文是产品分析与开发交接建议。本次核对了本地工作区源码、现有处理约定和官方公开资料；没有安装竞品进行同图实测，没有新增 Photoshop 原生验证。下文的优先级、界面方案、开发成本和效果预期属于分析判断，不是用户调研或性能测量结果。

本地基线：manifest 为 0.6.0，Git HEAD 为 `d276ec2`，工作区已有未提交修改。源码判断以当前工作区为准，不能仅按 HEAD 或发布包推断。后续 agent 应保留已有修改。

## 1. 产品方向与优先顺序

建议定位：**帮助新手在 Photoshop 中把星空照片处理到可继续精修的状态，并把最容易选错、最繁琐的星空专用操作收成少量步骤。**

Photoshop 已经擅长蒙版、图层、局部修补、曲线和创意调色。插件优先补足星点配准、背景梯度建模、线性天文图像进入照片后期、星点与主体分开处理这些环节；普通曝光、白平衡、水印、常规拼接等不必各写一套。

先做以下四件事，收益预计高于继续增加辉光、星芒或锐化按钮：

1. 让新手知道现在处理的是哪张照片、什么阶段、哪对星点与背景，以及下一步能做什么。
2. 提供保守的背景梯度校正，减少在 PS 中反复选区、模糊、相减、修正偏色的操作。
3. 补齐线性堆栈到可见照片的准备流程，清楚区分“显示提亮”和“修改像素”。
4. 简化已有星点加工参数，保证分离、预览、最终合成之间的关系明确。

### 三个会影响新手成败的现有边界

**线性母版与星点处理之间存在断点。** 堆栈可以保留负值和大于 1 的高光，而图层上传和现有拉伸、去星等算法入口检查 `0..1`。[上传检查](G:/code/2026/星点提取与重混合插件/backend/server.py:229)、[范围检查](G:/code/2026/星点提取与重混合插件/backend/algorithms.py:14)。因此，只增加一个“自动拉伸”按钮仍可能在上传时失败。必须设计准备阶段的数据入口与范围映射；不能靠全局 `clip(0,1)` 隐藏问题。

**“星空与固定地景”不是地景保护堆栈。** 当前只从匹配特征中排除固定地景，整张图仍随天空变换。面板已诚实提示地景可能拖花。[界面说明](G:/code/2026/星点提取与重混合插件/plugin/index.html:52)、[整图变换与累积](G:/code/2026/星点提取与重混合插件/backend/stacking.py:238)。改善命名应立即进行，真正的地景保留另立任务。

**图层角色主要依靠用户选择和混合状态。** 当前不自动选择分离后的星点与背景；编码识别依赖位深和线性光模式。[选择逻辑](G:/code/2026/星点提取与重混合插件/plugin/main.js:53)、[编码识别](G:/code/2026/星点提取与重混合插件/plugin/host.js:109)。这可以满足手动精修，但不宜作为未来自动流程唯一的图层身份依据。

## 4. 已有操作逻辑应该怎样改

### 4.1 入口按用户手里的素材组织

当前默认进入堆栈页。[当前默认](G:/code/2026/星点提取与重混合插件/plugin/main.js:6)。但已经在 PS 打开照片的人，可能只想压星、去光害或调整背景。

建议在现有面板顶部加一个很小的开始区，先保留现有页签：

- **处理当前照片**：有打开文档时优先呈现，进入相关工具。
- **从多张原片开始**：进入现有堆栈。
- 场景只分“银河 / 带地景”和“深空”；已保存的选择可复用，用户能随时改。

根据场景显示相关说明，不靠未经验证的图像分类器静默判断。开始区应能折叠，熟练用户仍可直接使用原有页签。先用小改动验证路径，再决定是否重排整个面板。

### 4.2 处理状态要解释“能不能做”，不能只显示位深

建议记录当前输入的来源、是否确认线性、是否已完成准备，以及像素范围。

- 32 位不必然是未拉伸线性图；16 位也可能仍为线性。
- 本插件生成的堆栈可携带已知状态；经 Camera Raw 打开后必须按实际文档重新确认，不能继续假定原 DNG 的线性状态。
- 外来图像无法可靠判断时标记“处理阶段未知”；只在操作依赖阶段时，给出“已显影照片 / 线性堆栈”的简短确认。
- 错误消息改成可执行的下一步，例如“此图仍含超范围高光，先创建后期副本”，同时保留技术详情供排查。

诊断应在昂贵推理前完成。合法 HDR 数据需要专门准备流程，不能被称为坏图片，也不能通过去掉全局检查让所有旧算法接收它。

### 4.3 分离后提供快捷衔接，保留手动选择

分离完成后增加两个显式按钮：**查看无星背景**、**使用刚分离的星点与背景**。

后一个按钮填写刚创建的图层对并进入加工预览，不按名称后缀猜测，不覆盖用户后续手动指定的来源。当前会话可先记录源文档 ID、两个结果图层 ID、分离方式和编码；当图层删除、复制或来源失效时返回手动选择。

重新打开 PSD 后的关联保存属于下一步能力，必须先验证可用的 PS 持久化方式。不要为了这个快捷按钮先造一套通用项目数据库。

### 4.4 默认混合跟随分离关系，高级混合保留给精修

基础界面显示“与分离方式匹配”及“恢复匹配设置”。滤色、相加、灰底修正各自跟随其来源约定；其他外观混合放进高级选项。灰底修正继续遵守现有编码与负差值保护。

32 位可用模式和 8/16 位不同，Adobe 的支持表没有包含 32 位滤色。[Adobe 官方 32 位支持说明](https://helpx.adobe.com/photoshop/desktop/adjust-color/hdr-and-channel-manipulation/features-that-support-32-bpc-hdr-images.html)。不要为了打开某个混合选项直接降低原文档位深。插件当前暴露的四种 32 位模式是其自身子集，也不能表述为 PS 仅支持四种混合。

对于外部导入的星点层，用户可以指定分离关系；当前根据混合模式推断灰底编码的方式，不足以支持所有未来自动化。已知来源与未知来源应有明确区别。

### 4.5 将“星点加工”改成新手能理解的少量控制

现有参数已经有保护能力，先改呈现和默认值来源，不立即换算法。

| 现有功能 | 基础界面建议 | 高级界面保留 | 应解释的边界 |
| --- | --- | --- | --- |
| 亮度曲线 | 星点亮度；暗星保留 | EV、三个曲线锚点 | 调星点亮度不等于调整整张图 |
| 缩星 | 缩星强度；保护亮星默认开启 | 半径、暗星阈值、高光保护起点 | 初始半径可由星点尺度建议，但不能对所有分辨率套同一个像素值 |
| 彗差减少 / 星形修复 | 改称“拉长星点修整”；默认关闭 | 检测阈值、圆度、搜索范围 | 这是模型圆星重建；不等同于光学恢复或 BlurXTerminator 反卷积 |
| 饱和度 | 星点颜色；亮星保护 | 保护起点 | 已完全过曝的颜色不能恢复 |
| 辉光 | 辉光强度；大小 | 亮度范围、过渡、外晕比例 | 默认关闭；作为个人风格选项 |

工具卡片展开不应自动启用效果；当前启用和展开分离的逻辑值得保留。预设最多先做“自然控星”和“柔和亮星”两项，且均显示启用了哪些效果、可一键还原。像素半径的适配必须保留实际值可见，避免预设成为黑箱。

现有“保留模型背景（减少彩色残留）”可改成更容易理解的说明，例如“彩色暗圈修正”，并保留原技术说明。是否默认开启要经过不同素材的 A/B 对比；当前有局部验证，不能据此替所有输入更改默认值。

### 4.6 预览沿用原生全分辨率，改善状态与比较

保留已有新标签页与完整尺寸预览，不改成只能看面板缩略图。建议补充：

- 预览文档标题标明源照片；面板持续显示来源。
- “查看原星点”之外增加“查看原合成”，比较时保持相同背景、缩放和显示设置。
- 显示“正在计算，当前仍是上次结果”；不把旧结果标成最新。
- 切换背景或混合只走已有原生更新；参数拖动仍采用现有最新请求机制。
- 重计算较慢的工具可增加“暂停自动更新 / 更新预览”，但沿用自动预览默认，不重新设置必点的预览门槛。

不承诺全分辨率所有参数即时更新。若以后提供局部快速计算，必须显式区分它与全图；涉及辉光、背景建模等需要上下文的算法，要带足邻域，不能把选区外影响直接截断。

### 4.7 应用结果时管理完整合成，避免星点重复叠加

当前执行路径创建可见的 `_processed` 星点并放到所选背景上方，但没有在此路径统一管理输入星点和历史加工结果的可见性。[写回代码](G:/code/2026/星点提取与重混合插件/plugin/star-processing.js:216)。源星点原本可见或用户连续应用时，是否双重叠星需要真机复现，本文不将其写成已验证缺陷。

建议定义一个清楚的应用结果：生成可开关的处理组，保留原层，避免新旧星点结果同时进入当前合成；记录和恢复需要改变的可见性。手动选择的其他内容不应被大范围隐藏。用户应能一键比较原合成、当前结果，并一次撤销本次写回。

验收要比较**最终文档合成与预览**，仅比较两张星点层的像素不足以证明成片一致。

### 4.8 堆栈用用途解释模式，先呈现可靠性

- 新手只显示“普通降噪”和“排除偶发亮线 / 异常像素”；高级选项保留五种模式。
- 样本较少时优先均值；Sigma 推荐条件以实际夹具和实拍验证确定，不硬写一个未经验证的通用张数门槛。
- 明确说明异常剔除可能同时去掉飞机、卫星与希望保留的流星，不默认替用户决定拍摄目标。
- 基准帧现为文件名排序后的中间帧；先显示它，并允许显式更换。自动选最佳帧是后续质量评估能力。
- 当前某帧配准失败会终止任务。先让用户看懂失败文件与原因，再提供“排除此帧并重试”；源文件不删，剩余帧不足时不继续。
- 已有匹配数、RMS、覆盖率与 JSON 记录，先呈现这些数据，再考虑加权堆栈和归一化。[现有配准记录](G:/code/2026/星点提取与重混合插件/backend/stacking.py:95)、[结果摘要](G:/code/2026/星点提取与重混合插件/backend/stacking.py:288)。
- 最大值模式当前也经过星点对齐，不能仅改名为“星轨合成”；真正星轨流程需要不同运动处理。

### 4.9 输出按下一步推荐，避免格式考试

不要简单把 DNG 默认换成另一个固定默认。可呈现三个用途，显示将生成的实际格式与位深：

| 下一步 | 建议路径 | 需解释的事项 |
| --- | --- | --- |
| 在 Camera Raw 中显影 | 现有 DNG | DNG 是已去马赛克的线性浮点输出；打开后的实际阶段和位深以 ACR 结果为准 |
| 保留母版并在插件继续处理 | 32 位 TIFF 母版 + 显式创建后期副本 | 先完成准备与拉伸，不能把未准备母版直接送入当前有限范围算法 |
| 在 Siril / 其他天文软件继续 | 32 位 FITS | 保留科学母版和元数据；不要让 PS 导出覆盖母版 |

16 位输出仍可保留在高级格式选项中。涉及压缩动态范围或量化时，界面说明实际改变，不能只写“兼容处理”。

### 4.10 首次使用与面板尺寸也属于功能体验

- 引擎设置集中显示“已就绪 / 缺少程序 / 缺少模型文件 / 许可待确认”，提供选择完整安装目录和打开官方说明的入口。
- 读取已有支持位置并预填候选，只在明确识别且验证成功后使用；不承诺识别任意电脑的所有安装。
- 保留现有许可肯定接受流程，避免把安装引导简化成跳过必要条款。
- 堆栈、控星等不依赖某个缺失引擎的功能仍可用，不能让可选引擎阻塞整个面板。
- 校准帮助直接说明“没有也可继续，但哪些问题可能无法修复”，不要增加一串必须学会的校准术语。已有 ISO / 曝光检查应复用，温度元数据不可靠时不能宣称匹配成功。
- 面板当前最小宽度 660 px。[manifest](G:/code/2026/星点提取与重混合插件/plugin/manifest.json:8)。建议把可窄栏停靠作为独立易用性改进，试验约 380–420 px 的单列布局，在实际 PS 中验证后再改声明；不承诺只改最小宽度即可完成。

## 5. 值得新增的功能及实施边界

### A. 背景梯度校正：新增功能首选

用户问题：画面一侧偏亮、偏黄，直接压黑后银河暗尘也没了。PS 可以手工完成，但操作多，用户难以判断该保护什么。

建议交互：**生成建议 → 查看要移除的背景 → 必要时涂抹保护银河 / 星云 / 地景 → 调整强度 → 应用为新图层**。新手只先看到强度；模型尺度或平滑度放进进阶选项。

首版建议直接使用现有数值计算依赖，实现保守的大尺度背景模型；先从低阶、稳健拟合开始，RBF 作为确认收益后的扩展。采样使用图像中的可靠背景块，排除亮星、主体保护区、透明区和无覆盖边缘；保护主体的区域不等于输出不校正的区域，应分别定义。

拟合前检查有效采样的数量、空间分布和模型条件。满幅星云、银河充满画面或只有一小块可用天空时，提示用户指定背景区域或跳过，不能强行把最暗像素都当成没有天体的天空。

输出除结果层外，可选保留隐藏的背景模型便于检查。在线性阶段按加性梯度建模；对于已显影照片，只承诺视觉上的渐变校正，不声称恢复了线性光害信号。暗角优先使用已有平场或合适的镜头校正；减法与除法不能混用。依据：[Siril 背景提取](https://siril.readthedocs.io/en/stable/processing/background.html)、[GradientXTerminator 原理与限制](https://www.rc-astro.com/gradientxterminator-tutorials-manual/)。

该任务不要求新手先安装 GraXpert 或 Siril。若评估后选择外部引擎，应先证明与内建基本方案相比的实际收益，再新增可选依赖。

### B. 受保护拉伸：与线性准备一起做

用户问题：堆栈后很黑；反复拉曲线后星点变大、颜色发白；看不出预览提亮是否保存。

建议初始界面只保留“提亮程度”“亮星保护”“背景亮度”，显示全图剪切提示，支持自动建议后微调。黑场不默认压到纯黑，默认通道联动，不能用独立通道拉伸悄悄重置已经做过的颜色校准。

工程上必须拆成三个清楚的状态：

1. **只看提亮效果**：显示变换，不改变母版像素。
2. **生成后期副本**：显式范围与色彩处理，记录映射和来源。
3. **在副本应用拉伸**：修改副本像素，并标记其已拉伸。

不要把这三个状态实现成每次点击都累乘一次曲线。所有预览从稳定输入与当前参数重算，应用后能够撤销。

现有 GHS / asinh 可复用，但 `stretch()` 本身仍要求 `0..1`，其颜色映射也不代表支持任意 ICC 下完全等价的物理亮度。先明确工作色彩空间、像素范围和转换边界，再决定哪些数学可直接沿用。

线性去星是一项单独能力：Siril 有专门的 MTF 预拉伸 / 逆变换流程，StarXTerminator 也说明模型对星点轮廓与拉伸方式敏感。[Siril StarNet 文档](https://siril.readthedocs.io/en/stable/processing/stars/starnet.html)、[StarXTerminator 官方使用说明](https://www.rc-astro.com/starxterminator-usage-notes/)。因此，不能设计成“先随意强 GHS，再统一去星”。首版可先支持确认过的非线性照片路径，保留线性母版；线性去星另做数值与实拍验收。

### C. 保护蒙版：优先输出到 Photoshop

建议提供“保护星点”“只处理无星背景”“保护主体”三个任务入口，从已有信号、检测和用户选区生成可编辑的原生蒙版或选区。

星点层是用于重合成的像素信号，不等于质量合格的保护蒙版。灰底修正星点包含编码与负差值，不能直接取灰底亮度当蒙版。应先按已知编码获得正星点信号，再做适当扩展与柔化；让用户能看到覆盖范围。

首版不要求自动识别全部星云或精细地景。PS 原生选区与用户涂抹可以成为主体保护来源，避免再造一套通用抠图系统。

### D. 背景偏色修正与颜色增强

建议先提供“用此处作为天空背景”的局部取样，结果以可调整的图层或蒙版承载。银河地景不要默认把整片天空变成灰色；天空自然色彩、地景灯光和天体颜色可能有意保留。

星云 / 银河色彩增强应保护暗背景噪声和亮星，不再只增加一个全图饱和度滑块。星点色彩控制已经存在，应复用。

测光颜色校准暂后置：它需要合适的线性输入、星表与解析等前提。对已经多次调色的 PS 图像，不应显示“自动校准真实颜色”这种承诺。[Siril SPCC 前提](https://siril.readthedocs.io/en/stable/processing/color-calibration/spcc.html)。

### E. 背景降噪：值得做，但先验证接入方式

先比较三条路径的实际收益与操作成本：PS 已有可用降噪流程、一个简单的内建背景色噪工具、一个可选的天文专用引擎。不得为凑齐功能把三套都塞进首页。

若使用外部引擎，第一轮只适配一个已核对版本及输入约定的工具。GraXpert 的公开 CLI 可作为候选；用户自有 NoiseXTerminator / DeepSNR 也可以作为分工路径，但能否自动调用，要以各自公开接口和授权为准。[GraXpert 官方接口](https://github.com/Steffenhir/GraXpert/blob/main/README.md)、[RC-Astro 当前套装与 CLI 说明](https://www.rc-astro.com/software/photoshop-bundle/)、[DeepSNR PS 输入限制](https://starnetastro.com/ps-plugins/deepsnr/)。

基础控制只放强度与细节保护；默认以背景或无星区域为作用对象，提供等显示条件的前后比较。处理在线性还是非线性阶段由实际算法前提决定，不能统一写成所有降噪都必须在拉伸后进行。

### F. 地景保留：分两阶段完成

第一阶段：从堆栈输出天空结果与**未随天空变换的参考地景**两层，允许用户在 PS 用天空蒙版融合。界面清楚写明参考地景来自一帧，它没有获得多帧地景降噪收益。

第二阶段：有明确使用需求和样片后，再实现固定机位的独立地景堆栈与羽化融合。遮挡边界、树枝、移动水面、赤道仪素材另行处理，不能把现有红色“对齐排除蒙版”直接当最终天空选区。

这个方向对银河用户很有价值，但开发与验收都比“自动涂黑地景”复杂，应在基础流程稳定后实施。[Sequator 官方地景流程](https://sites.google.com/view/sequator/manual)。

### G. 堆栈质量与有效边界

先展示已有数据：逐帧匹配数 / RMS、处理失败、有效覆盖范围，以及建议裁剪框；裁剪先预览、后应用，保留未裁剪母版。

再考虑星点尺度、拉长程度、背景亮度和噪声等建议指标。它们依赖取样区域与拍摄内容，不能用一个分数把薄云、银河密集区、地景误判成同一种坏帧。建议排除应能复选与撤回。

当前虽在内部累计覆盖率，但摘要只保留最小 / 最大值。完整覆盖图、建议裁剪和可视化质量列表仍需实现，不能当作现成 UI。

帧间亮度归一化和加权作为后续数值任务。尤其在现有强调不做逐帧曝光归一化的约定下，需要显式模式、记录参数并验证颜色与剔除行为，而不是静默改变旧模式。[Siril 堆栈说明](https://siril.readthedocs.io/en/stable/preprocessing/stacking.html)、[PixInsight 官方整合实例](https://www.pixinsight.com/examples/M31-Ha/)。

### H. 残星、暗圈与蓝紫晕：先做局部辅助

去星残留与拍摄本身的光学色晕不是同一类问题，建议拆开：

- 去星残留：提供原图 / 模型背景 / 当前合成的局部比较，辅助画保护或修复蒙版。
- 蓝紫晕：围绕亮星检测色晕候选，控制色度或局部强度，保留主体与非候选颜色。

首版可在副本和蒙版中引导用户使用 PS 局部修补工具，不以生成式内容自动补星云细节。不默认二次去星、整图模糊或大范围压紫色。Astronomy Tools 中同类功能可作为问题拆分参考，不能视作已验证的算法效果。[官方功能表](https://prodigitalsoftware.com/AstronomyToolsActions.html)。

### I. 外部堆栈导入

当前输出已有 FITS 路径，但堆栈输入扩展名列表没有通用 FITS。[输入列表](G:/code/2026/星点提取与重混合插件/plugin/stack.js:4)。建议以后支持“导入一张已堆栈 FITS”，桥接到带明确颜色、线性状态和范围记录的临时 32 位 TIFF，而不是先扩成完整序列管理器。

先支持边界清楚的单色 / RGB 文件；无法解释颜色空间或数据布局时应说明缺少的信息。保留原文件与元数据；裁剪或几何变换之后，WCS 应更新或标记失效，不能照抄旧解析信息后宣称仍然有效。

## 6. 两条面向新手的目标流程

### 银河 / 地景，当前照片已完成基本显影

1. 使用当前照片，确认银河 / 地景场景。
2. 可选：校正背景不均，保护银河和地景；已有满意背景可跳过。
3. 需要独立控星时再分离；只想改背景的人不必强制去星。
4. 用“使用刚分离的结果”进入；自然控星从一个强度开始。
5. 需要时调整背景与星点颜色；辉光和星形修整保持可选。
6. 查看原合成与当前合成，应用为可开关的图层结果，继续 PS 精修。

若从多张未跟踪原片开始，前置现有堆栈；在地景保留尚未完成前，不能展示“自动保留清晰地景”的承诺。

### 深空，输入为未拉伸堆栈

1. 保留线性母版，检查范围与有效边界。
2. 在已定义的线性路径中做必要背景校正；需要科学颜色校准时，可转 Siril 等完成后再接回。
3. 根据所用引擎的前提选择去星位置。只支持非线性输入的路径，先通过验证过的保守准备流程；未经实现的线性去星入口保持不可用。
4. 独立调整无星背景与星点；大幅主体拉伸尽量放在分离后，避免星点随之膨胀。
5. 降噪按对应算法要求安排；不把它强制锁到所有素材相同的位置。
6. 使用匹配的重合成方式，核对高光、星色和残留，输出 PS 图层结果。

流程卡只推荐下一步，所有可选处理均能跳过；不把它实现成必须依次点完的长向导。

## 7. 给 AI Agent 的实施任务

以下是按依赖排序的开发建议。一次只实施一个任务包；完成对应验收后，再进入下一包。成本高的任务先形成可审查的小范围数据约定，避免一次重写面板与图像管线。

### T1：开始引导与诚实的前提说明

目标：用户有 PS 当前照片时，能直接开始；从原片开始时仍能找到堆栈；不会把现有地景对齐模式理解为保留清晰地景。

范围：开始区、当前输入提示、操作前检查文案、地景模式命名、首次引擎状态。复用现有服务和设置，不增加新模型。

主要位置：[index.html](G:/code/2026/星点提取与重混合插件/plugin/index.html:1)、[main.js](G:/code/2026/星点提取与重混合插件/plugin/main.js:53)、[stack.js](G:/code/2026/星点提取与重混合插件/plugin/stack.js:6)。

验收：无文档 / 已有照片 / 预览文档激活 / 缺失可选引擎四种状态都有可理解且可完成的路径；不需要 RAW 堆栈的人不会被卡在文件选择；现有手动路径仍能执行。

### T2：分离到加工的衔接与最终合成

目标：刚分离的结果可以一次显式操作带入加工，默认恢复相应混合；最终可见合成与预览一致。

范围：当前会话的图层对记录、快捷入口、匹配混合、结果可见性与撤销。暂不做跨 PSD 的自动追踪系统。

主要位置：[extract](G:/code/2026/星点提取与重混合插件/plugin/main.js:206)、[refreshBlendModes](G:/code/2026/星点提取与重混合插件/plugin/main.js:68)、[执行加工](G:/code/2026/星点提取与重混合插件/plugin/star-processing.js:203)、[host](G:/code/2026/星点提取与重混合插件/plugin/host.js:103)。

验收：手动选择不被后台抢走；重命名不影响同会话关联；删除结果或换文档不误用；灰底负差值保持；输入星点本来可见与连续应用时没有重复叠星；一次撤销恢复本次输出与相关可见性。

### T3：星点参数分层与比较

目标：缩星、亮度、颜色的常见操作各能从一个主要控制完成，高级参数仍可访问。

范围：基础 / 高级呈现、术语和默认预设映射、原合成比较、计算状态。保持现有算法与完整分辨率预览路径。

主要位置：[tools 定义](G:/code/2026/星点提取与重混合插件/plugin/star-processing.js:3)、[参数生成](G:/code/2026/星点提取与重混合插件/plugin/star-processing.js:107)、[style.css](G:/code/2026/星点提取与重混合插件/plugin/style.css:1)。

验收：零强度 / 重置得到定义清楚的原效果；只展开卡片不启用；基础与高级显示同一设置；慢任务不把旧结果标成最新；不同尺寸素材的初始半径有验证依据。

### T4：线性准备入口与色彩、范围约定

目标：合法的负值 / 超范围高光母版能保留，并形成可供后续处理的显式副本；新手知道显示提亮是否已应用。

范围：为准备操作定义独立的浮点传输与处理约定，确认 ICC / 线性状态、映射、预览及保存；先做一种明确支持的母版来源。不要全局放松 `validate_image()`，也不要偷偷降为 8/16 位。

主要位置：[server 图像上传](G:/code/2026/星点提取与重混合插件/backend/server.py:224)、[stack_io](G:/code/2026/星点提取与重混合插件/backend/stack_io.py:307)、[stretch](G:/code/2026/星点提取与重混合插件/backend/algorithms.py:223)、[host.upload](G:/code/2026/星点提取与重混合插件/plugin/host.js:25)。

验收：含负值与大于 1 高光的合成母版通过准备路径，不改变原像素；NaN / Inf 仍被拒绝；记录范围映射；不会重复拉伸；sRGB、Adobe RGB、Display P3、线性 ProPhoto 等声明支持的配置有数值或真机证据。无法完成范围或色彩保证时，缩小支持范围，不能以硬裁切通过验收。

### T5：基本背景梯度校正

依赖：先完成 T4 的输入约定。可以先在已确认已显影的照片子集试验模型，但此时不能宣称支持未准备线性 HDR。

范围：低阶稳健背景模型、主体保护、模型预览、强度、新图层输出。先用现有数值计算依赖，不同时接入多个外部引擎。

候选位置：新增职责单一的背景模块，在现有后台任务和图层事务中接入；不要把背景工具塞进仅处理星点信号的 `process_stars()`。

验收：已知平面梯度的合成图在保护主体后能去除该梯度；已知弥散主体不会被当成背景抹掉；采样不足时能修正取样或跳过；透明区与低覆盖边缘不污染拟合；同一参数的预览与最终层在定义的精度内一致。

### T6：受保护拉伸界面

依赖：T4；以确定的输入约定审查现有数学后实施。

范围：自动建议、少量基础控制、剪切反馈、稳定输入重算、显示与应用分开。线性去星不在本任务内默认顺带实现。

验收：暗背景与高光测试图没有非预期新增裁剪；保留颜色的结论经过对应工作空间验证；外来已显影照片不会自动再做初始拉伸；原生显示与实际输出分清。

### T7 以后：一次只挑一个收益已经确认的扩展

按目标用户选择下一项：以银河地景为主，优先参考地景分层；以深空为主，优先保护蒙版与背景降噪。质量列表、FITS 导入、蓝紫晕修正随后按实际样片和使用需求排队。

不要同时立项“通用引擎框架 + 模型市场 + 全自动流程编辑器”。这些不是本轮所需的最小实现。

## 8. 验收素材与成功标准

### 必要素材

| 素材 | 主要验证目标 |
| --- | --- |
| 已显影广角银河，带山脊与灯光 | 背景取样不破坏银河与地景；说明是否清楚 |
| 纯星野，小而密的星点 | 缩星不消掉大量暗星；分离与合成一致 |
| 发射星云与暗云 | 背景校正、降噪不会以抹掉弥散结构换来“更干净” |
| 星系与明显光晕 | 星点识别 / 圆星修整不误伤星系 |
| 线性 32 位，含负值和超范围高光 | 准备路径、源数据保留、范围映射 |
| 8 / 16 位、灰度 / RGB、带透明区的图层 | 原有支持范围不回退，编码与 alpha 正确 |
| 原星点可见、重复应用、重命名、多文档切换 | 图层关联、可见性、缓存和最终合成 |
| 不同曝光、薄云、跟踪失败、飞机或流星的序列 | 失败反馈、建议排除、用户目标与模式选择 |
| 24MP 及项目常用全尺寸素材 | 完整尺寸预览、内存与磁盘、取消后清理 |

使用有授权的本地样片；不要把私人照片或外部模型输出直接加入公开仓库。可公开的数值测试优先使用可解释的合成夹具。

### 两层验证不能互相代替

算法与界面自动检查应覆盖输入约定、参数等价、图层选择、状态转换及取消；涉及 PS 混合、ICC、位深、写回与撤销的结论，需要真实 Photoshop 验证。已有验证记录只覆盖其中部分场景。[现有验证边界](G:/code/2026/星点提取与重混合插件/VALIDATION.md:3)。

新增测试围绕行为风险，不写只是复述参数赋值的测试。只改文字或低风险布局时，以实际可用性检查为主；修改浮点管线、编码或合成关系时，必须有有意义的数值与原生比较。

### 用户可用性目标

以下是建议验收目标，尚未测得：

- 未使用过该插件的人，无需读开发文档，就能从一张已显影照片完成一次背景校正或自然控星，并找到撤销。
- 从刚分离结果到加工，不需要自己推导星点层、背景层和混合模式的对应关系。
- 用户能区分“只是预览提亮”“已创建后期副本”“已经应用拉伸”。
- 不强迫用户使用与当前目标无关的堆栈、校准或去星。
- 有问题时提示具体下一步，不只给算法异常或外部 README 路径。

建议用 3–5 名真正的入门用户做小规模观察，记录完成率、卡住位置和错误操作；这用于发现流程问题，不能作为代表全部用户的统计结论。无须添加联网遥测才能进行这轮验证。

请先阅读本报告及当前仓库的 AGENTS.md / 用户指令。目标是降低 Photoshop 星空后期入门门槛，同时保持现有图像、色彩、编码和原生预览约定。

本轮只实施 T1 和 T2。先给出具体修改范围、现有行为证据和验收点，再完成实现与对应验证。不要顺带实现新拉伸、背景算法、降噪或地景堆栈，也不要整体重写面板。

T1：提供“处理当前照片 / 从多张原片开始”的轻量入口，解释当前阶段与工具前提，修正地景模式可能引发的误解。外来图像阶段未知时，不通过位深或直方图强行认定线性状态。可选引擎缺失不阻断不依赖它的功能。

必须保留完整分辨率 PS 原生预览、灰底 / 有符号编码的负差值保护、当前高级手动操作以及原始色彩配置和位深约定。不把修改全局像素范围检查、自动 clip、降采样或降低位深作为捷径。

完成后报告：实际修改、自动验证结果、真实 Photoshop 验证结果、尚未验证的范围。没有真机证据时明确写未验证，不宣称流程已经可发布。其余 T3–T7 保持为后续建议。
