# 32位负差值星点的上传修复

基线`30f6b02`，开发版本0.24.5。没有新增加工效果或放宽普通照片的范围要求。

## 复现与根因

2026-10-23原生格式矩阵在256×192 RGB32、嵌入Display P3、相加星点中复现：首次预览可以通过PS直接复制图层显示，但启用辉光后，含−0.025差值的星点上传被普通`/images`入口的0..1检查拒绝。后台`process_stars`已有有符号差值支持，面板上传却尚未衔接，因此不能用既有算法单测证明这条实际路径可用。

测试夹具另曾因按名称创建Display P3文档失败；随后改为打开带嵌入ICC的生成TIFF，并继承文档配置。这个测试脚本问题与上述真实上传缺口分别保留记录，未改生产色彩代码。私人证据在忽略目录`artifacts/native-formats-20261023/`。

## 修改范围

- 新增独立`/star-sources`入口：RGB/灰度差值为有限−1..1，透明度仍为0..1；按顺序完整上传，非法块不写入、不推进完整状态。复用现有有限来源与透明度检查，没有裁切、零点偏移或位深转换。
- 只有明确的有符号星点加工可以读取这类来源。普通照片、去星及其他专用来源的约束不变；既有普通图像形式的有符号算法结果仍兼容。
- 面板自动预览和直接执行共用同一上传函数；失败上传通过对应入口清理，换源/清空时也删除对应专用来源。结果仍走普通结果读回路径。

## 当前证据与边界

新增HTTP与控制器用例在修改前失败：HTTP不识别新入口、面板仍发送到普通入口。修复后，七项HTTP检查通过，覆盖逐位保留负值/极暗值/alpha、来源隔离、缓存清理及非有限/越界数据拒绝；控制器检查覆盖预览与直接执行的上传和清理。完整Python488通过、1项既有符号链接权限跳过、5条既有第三方警告；Node287通过。

全新冻结的0.24.5组件已在独立8766端口验证：专用上传逐位保留负值与极暗值，中性及实际改变像素的辉光结果与源码逐位一致；普通入口/作业隔离、非法块拒绝且不推进上传通过。不是沿用旧0.24.4运行库。

Photoshop27.1隔离面板的256×192原生矩阵全部通过，共199条断言、11个组合：8位黑底/sRGB的正常、变亮、滤色、颜色减淡、线性减淡、浅色；16位灰底差值/Adobe RGB的线性光；32位有符号差值/Display P3的正常、变亮、线性减淡、浅色。每个组合的全图RGB预览/最终合成、原星点、原背景及一次撤销最大差异均为0，预览尺寸/位深/文档ICC一致。32位夹具实际含−0.025星点及1.4背景；PS报告打开后的配置为`Display P3 (线性 RGB 配置文件)`，不宣称打开前后ICC字节相同。32位不支持的模式没有列出，灰底关系锁定线性光。此处是控件事件驱动真实模块/后台/PS对象，不是全部鼠标流程或画质验收。

开发安装包已构建并以`--extract-only`抽取核对，公有插件、执行运行库和文档一致，私人配置、照片和外部引擎未混入；第三方源码及SHA256随包生成。本次仅安装/卸载临时Core Test，正式0.10.0未动，不宣布生产权限、干净电脑安装或Release发布完成。

独立克隆撤销本阶段实现提交`00fecb8`后，受控文件精确恢复`30f6b02`，旧版286项Node通过。源文件与处理算法不变；源码回退不撤销照片或正式安装。私人证据包括`native-formats.json`、`frozen-signed.json`、`package-verification.json`和`rollback-30f6b02.json`。ICC名称断言的夹具失败记录与此前真实负值上传失败分别保留，没有据其放宽生产数据约束。
